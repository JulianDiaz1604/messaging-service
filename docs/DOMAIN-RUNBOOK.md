# Domain Runbook — messaging-service

Living reference for the domain behavior of `messaging-service`. Updated with **every HU**:
business rules, invariants, and the custom-exception → message → HTTP-status mapping.

## Conventions

- Validation errors extend `DomainException` → **HTTP 400**.
- Conflicts extend `RuntimeException` with a dedicated handler → **HTTP 409**.
- Not found → dedicated exception → **HTTP 404**.
- Authorization / wrong credential → dedicated exception → **HTTP 403**.
- Upstream / integration failures → dedicated exception → **HTTP 502**.
- Business rules live in `domain/validation/*Validator`; use cases delegate to them.
- `ControllerAdvisor` maps every exception and returns `{ "message": ... }`.

## HU14 — Notify that the order is ready (SMS + security PIN)

- **Endpoints:**
  - `POST /api/v1/notifications/order-ready` → notify client
  - `POST /api/v1/notifications/{orderId}/validate` → validate PIN
- **Use case:** `NotificationUseCase`
- **Validator:** `NotificationValidator`
- **SMS adapter:** `SnsSmsAdapter` (AWS SNS via SDK v2)
- **Persistence adapter:** `NotificationJpaAdapter`

### Business rules / invariants

1. **Required fields**: `orderId` (UUID) and `phone` (string) are mandatory for `order-ready`.
   `orderId` and `pin` are mandatory for `validate`.
2. **Phone format**: digits only, may start with `+`, max 13 characters
   (regex `^\+?[0-9]+$`, max length 13). Validated in `NotificationValidator`.
3. **PIN generation**: a 6-digit numeric PIN is generated by `PinGenerator.generate()` using
   `java.security.SecureRandom`. The PIN is zero-padded to exactly 6 characters (e.g. `004321`).
   The domain is free of AWS SDK dependencies — the PIN is pure domain logic.
4. **No duplicate notifications**: if a notification already exists for a given `orderId`, the
   use case throws `NotificationAlreadySentException` (HTTP 409). Regenerate-and-resend is NOT
   allowed. The caller must use the original PIN already sent by SMS.
5. **SMS-first, then persist**: the SMS is sent before the notification is saved to the database.
   If AWS SNS delivery fails, the notification is NOT persisted, allowing the caller to retry.
6. **PIN not returned in HTTP response**: the PIN travels only via SMS. The `order-ready` response
   contains only `id`, `orderId`, and `status`. Returning the PIN in the HTTP response would
   undermine its security purpose.
7. **PIN validation**: the stored PIN for the `orderId` is compared with the submitted PIN. An
   exact string match is required. Mismatches throw `InvalidPinException` (HTTP 403). Unknown
   orders throw `NotificationNotFoundException` (HTTP 404).
8. **NotificationStatus enum**: `SENT` is set on successful delivery; `FAILED` is reserved for
   future use (e.g. async delivery tracking).

### Exception → message → HTTP status

| Exception | Message (from `DomainConstants`) | HTTP Status |
|-----------|-----------------------------------|-------------|
| `RequiredFieldException` | "All fields are required" | 400 |
| `InvalidPhoneFormatException` | "The phone must be numeric, may start with '+', and have at most 13 characters" | 400 |
| `NotificationAlreadySentException` | "A notification has already been sent for this order" | 409 |
| `NotificationNotFoundException` | "No notification found for the given order" | 404 |
| `InvalidPinException` | "The provided PIN does not match the one sent to the client" | 403 |
| `SmsDeliveryFailedException` | "The SMS could not be delivered; please try again later" | 502 |

### Layering notes

- `NotificationValidator` is a pure domain class — no ports, no Spring, no AWS SDK.
- `SnsSmsAdapter` lives in `infrastructure/out/sns/` and implements `ISmsSenderPort` (domain SPI).
  The domain throws `SmsDeliveryFailedException` (a domain exception) even though the trigger is
  an AWS SDK failure — the adapter catches `SnsException` and re-throws the domain exception,
  keeping the domain free of infrastructure leakage.
- `SnsClient` is wired as an `@Bean` in `BeanConfiguration`. The region and optional LocalStack
  endpoint override are read from `aws.sns.region` and `aws.sns.endpoint` respectively.
- The `SnsClient` does NOT make network calls during construction, so the Spring context loads in
  CI/H2 test mode without real AWS credentials.
